# Речник

Термините се дефинират веднъж тук; останалата книга ги използва само с тези значения.

| Термин | Значение |
|---|---|
| **Агентен режим** | Командата `create`: модел пише чернова, конвейерът работи, провалите се връщат като поправки на спецификацията. |
| **Административен надзор** | Стъпката при разгръщане, която добавя административен CRUD за всеки модел без такъв. |
| **Автоматичен режим** | LLM обмен, който инструментът прави сам, при зададен `ANTHROPIC_API_KEY`. |
| **Компилационна порта** | `dotnet build`, който един етап трябва да мине, за да е готов. |
| **Отметка** | Име на етап, записано в `plan/state.json` на проекта, след като този етап успее. |
| **Кодов указател** | Именуван ориентир (`searchEngine`, `sorting`, `imageCrudLogic`, …), който `report` превръща във файл, ред и откъс. |
| **Дизайн-пресет** | Именуван набор токени (акцент, неутрални, шрифтове, дълбочина) върху Bootstrap тема, закачен в `meta.style.preset` или избиран за всеки проект (още не възпроизводимо — виж [глава 12](12-principles.md)). |
| **Отклонение** | Декларативна промяна на контролер, създаден от scaffold: `removedActions`, `redirects`, `sorting`, `pagination`, `ownership`. |
| **`displayName`** | Българският надпис на свойство; задължителен за всяко видимо съхранено свойство. |
| **DTO** | Съставен модел за четене над няколко същности. Свързан, но неизпитан. |
| **Фрагмент на функция** | JSON файл в `feature-templates/`, който добавя модели (понякога и контролери), когато функцията е включена; страниците на функцията идват от шаблони. |
| **Файлов договор** | Правилото (ADR-005) всеки LLM обмен да е файл заявка + файл отговор. |
| **Порта** | Всяка проверка, която спира генерирането: схема, компилация, миграция, `verify`. |
| **Генериран резултат** | Всичко под `out/`. За изхвърляне, никога не се редактира. |
| **Идемпотентен етап** | Безопасен за повторно пускане: разпознава свършеното си. |
| **Инсталационен корен** | Папката само за четене на инсталираната програма. |
| **`isLookup` / `isSpecification`** | Флагове, които преместват малки модели на страница „Спецификации“. |
| **Езикова проверка** | Сканирането за английски в `verify`; пропуска се при небългарски проект. |
| **Lock файл** | `project-spec.lock.json` — разгърнатата спецификация, която етапите четат. |
| **Проверка на манифеста** | Сравнението на обещаните файлове с наличните на диска. |
| **Ръчен режим** | LLM пътят без ключ: инструментът пише заявка и излиза с код 3. |
| **Собственост** | Правило на контролер (`{ "userProperty": "UserId" }`), налагано на сървъра. |
| **`parentRef_<Target>`** | В seed ред: `refKey` на родителя. |
| **Произход** | `generatedBy` на контролер: `scaffold`, `template`, `writtenFromScratch`. |
| **`refKey`** | Уникално символично име на seed ред. |
| **Възобновяване** | Продължаване от първия незавършен етап. |
| **Seed** | Вторият вход: по един масив редове за модел. Също и етапът. |
| **Seed потребител** | Потребител, създаден от `IdentitySeeder` от `identity.seedUsers`. Освен ако спецификацията не зададе парола, тя се извежда от seed стойността за разнообразие и имейла; всички се записват в `logs/<Project>/seed-credentials.txt`, а банерът показва един администратор и един обикновен потребител. |
| **Спецификация** | `project-spec.json`, декларативното описание на приложението. |
| **Етап** | Една стъпка от конвейера: `IStage` с име и идемпотентен `RunAsync`. |
| **`$seedUser:N`** | Заместител в seed редове: „N-тият seed потребител“. |
| **`$primaryModel`** | Токен във фрагмент, заместен с основния модел на проекта. |
| **`$variation:axis`** | Заместител, който разгръщането заменя с решената стойност. |
| **Неподдържано искане** | Запис в `meta.unsupportedRequests`. |
| **Ос на разнообразието** | Една от единадесетте стилови настройки, решена веднъж за проект. |
| **`verify`** | Етап 8 и определението на продукта за готово: компилация, миграция, манифест, стартиране, `/`, вход на администратора, декларираните маршрути (не-200 се записва в лога и не е фатално), език. |
| **Работна папка** | Папката за писане: `Documents\DPS-NN` при инсталация, коренът при разработка. |
