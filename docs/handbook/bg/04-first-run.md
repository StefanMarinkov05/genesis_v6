# Първото ви генериране

**Нужни са:** Windows с .NET 10 SDK, SQL Server Express LocalDB, `dotnet-ef` 10.x и `dotnet-aspnet-codegenerator`. На Linux генераторът се компилира и тества, но базата на генерираното приложение не работи — очаквано е генерирането да спре при първото извикване на `ef`.

Проверете машината, преди да обвините инструмента:

```bash
dotnet run --project src/Genesis.Cli -- doctor
```

`doctor` отпечатва по един ред за всяка предпоставка с точната команда за поправка. GUI го изпълнява при всяко стартиране и показва доклада в дебъг терминала си.

## Компилиране и генериране на фикстурата

```bash
dotnet build
dotnet test
mkdir -p prompts/in
cp seeds/facenote-rich-seed.json prompts/in/seed-response.json
dotnet run --project src/Genesis.Cli -- run --all --spec fixtures/project-spec.facenote.json --out out
```

Защо копието: етапът `seed` иска данни от модел, освен ако вече няма отговор. Ако поставите доставения seed там, където би бил отговорът, цялото генериране минава **без мрежа и без ключ** — ръчният и автоматичният път са един и същ файлов договор. Снимките се изтеглят първия път и се кешират.

Наблюдавайте конзолата. Всеки етап се обявява (`=== stage: seed ===`), а генерирането завършва с таблица с времената и банер (в конзолата е нарисуван в рамка; имената на ролите се менят според проекта):

```text
FaceNote
  http://localhost:5xxx
  Admin            admin@facenote.bg / <derived password>
  Client           user@facenote.bg / <derived password>
(4 more seed user(s) - full list: logs/FaceNote/seed-credentials.txt)
Database: <database name>
Start: dotnet run --project "out/FaceNote"
```

Освен ако спецификацията не задава парола, паролата на всеки seed потребител е **производна**: извежда се от seed стойността за разнообразие на проекта и от имейла на потребителя, така че една и съща спецификация винаги отпечатва едни и същи данни, а два проекта никога не делят парола. Банерът показва един администратор и един обикновен потребител; пълният списък е във файла с данни за вход, който банерът назовава.

## Ако излезе с код 3

Код `3` не е провал — означава, че LLM обмен чака файл. Заявката вече е записана; поставете отговора в `prompts/in/<stage>-response.json` или задайте `ANTHROPIC_API_KEY`, после пуснете с `--resume`. Някои стъпки задават въпрос в терминала: `spec build` винаги пита за конвенциите за времеви печати (`conventions.timestamps.createdAt? [y/n]`), а когато кандидати за seed файл са няколко, се появяват менюта за избор; `--no-interactive` превръща всеки такъв въпрос в грешка, вместо в подкана.

## Какво да разгледате

| Път | Защо |
|---|---|
| `out/FaceNote/` | самото приложение; `dotnet run` вътре и вход с данните от банера |
| `out/FaceNote/dps-nn.log.jsonl` | граници на етапи и времена — това следи GUI |
| `out/FaceNote/plan/state.json` | кои етапи са завършени; изтриването налага чисто пускане |
| `wwwroot/output/verify-language-report.txt` | присъдата на езиковата проверка, успех **или** пропуск |
| `logs/registry.json` | кой проект от коя спецификация и кой seed е произлязъл |
| `prompts/out/schemas/`, `prompts/out/seeds/` | постоянен архив на използваното |

## Повторно пускане и какво значи „възобновяване“

`run --all` пропуска етапите, записани в `state.json`. Това е желаното след срив и обикновено нежелано след промяна в шаблон; тогава наложете частта, която сте сменили:

```bash
dotnet run --project src/Genesis.Cli -- run --all --spec fixtures/project-spec.facenote.json --from emit-controllers-views
```

`--from` пуска отново този етап и всички след него. `spec-expand` върви първи при всяко извикване, освен ако собствената му отметка не казва „готово“; `spec-build` не е част от цикъла ([глава 9](09-workflow.md)).

## Най-бързият начин да го счупите нарочно

Направете го веднъж; учи повече от всяка глава:

1. Отворете `out/FaceNote/Areas/Client/Views/Products/Index.cshtml` и сменете български надпис с английски.
2. Пуснете с `--from verify`.
3. Прочетете провала: езиковият доклад назовава страницата и цитира текста.

После отменете промяната и пуснете същата команда: отново минава. Обърнете внимание къде трябваше да направите поправката: резултатът е генериран, така че при истинска промяна поправката е в `templates/`, никога в `out/`.
