# Индекс на решенията

Всяко структурно решение е записано като ADR в `docs/adr/`. Тези файлове са авторитетът: контекст, алтернативи и последствия; не се редактират, а замененото решение пази номера си и бележка какво го е заместило. Тази глава е индексът — четете реда и следвайте връзката, когато „защо“ има значение.

| ADR | Решение | Какво дава | Какво струва |
|---|---|---|---|
| **001** | Три файла: спецификация / lock / state | разгръщането е безопасно; възобновяването не пипа входа | още един файл за разбиране |
| **002** | Локализация на Identity чрез статична карта | детерминистично, не чупи Razor | работи само за известни низове |
| **002b** | Основните Identity страници се излъчват изцяло | пълен български текст и стил | повече шаблони |
| **003** | Символни връзки в seed-а | seed-ът преживява повторни пускания | родителите се вмъкват първи (топологично) |
| **004** | Детерминистично разнообразие (хеш на seed + ос) | разнообразно и стабилно | авторът на спецификацията не може да „рандомизира“; изборът на пресет още се отклонява ([глава 12](12-principles.md)) |
| **005** | LLM етапите са файлов договор | офлайн режим, одит, тестове | два файла на обмен |
| **006** | Отклонения с regex върху известни форми | евтино и шумно при промяна | чупливо по строеж |
| **007** | Меко изтриване с глобален филтър | никоя заявка не го забравя | още един базов клас |
| **008** | Оформление като слой от токени | различен вид без шаблонни редакции | дизайнът живее в пресета |
| **009** | Граница на преименуването | без счупване на вътрешности, фикстури, логове | два речника |
| **010** | GUI е Electron обвивка над CLI | една реализация | GUI зависи от формата на лога |
| **011** | Кеш на снимките + резервни варианти | бързо повторно генериране, без директни връзки към външни снимки | още една папка |
| **012** | Обобщена страница „Спецификации“ + филтри | навигацията остава четима | два флага по правило |
| **013** | Агентът пише и поправя само спецификацията | резултатът остава чист шаблон | моделът не може да поправи шаблон |
| **014** | Инсталационен корен само за четене | програмата не пише до себе си | два корена за ресурси |

## Трите, които са принципи

1. **ADR-001 и 005** правят генерирането одитируемо: входовете са неизменни, разгръщането е отделен артефакт, приносът на модела е файл.
2. **ADR-013 е границата на доверието.** Ако моделът можеше да редактира генериран код, нито едно приложение нямаше да е обяснимо.
3. **ADR-004 и 008** отговарят на въпроса защо двадесет приложения не изглеждат еднакви — и защо отговорът е замислен като детерминистичен, а не случаен. Изборът на пресет още ползва `GetHashCode()`; докато не започне да ползва същия SHA-256 като осите, закачете го в спецификацията.

## Предложения, които кодът още не е приел

Полезно е да се запишат, преди да се приеме това издание. (Две по-ранни предложения — справочник за анатомията на генерираното приложение и писмен договор за seed — са изпълнени: `docs/explanation/generated-app-anatomy.md` и `docs/reference/seed-format.md`.)

| Предложение | Защо |
|---|---|
| Да се оттеглят отделните документи в полза на тази книга | един източник на факт; днес обзорът, урокът и справочникът се повтарят |
| `--from spec-build` / `--from spec-expand` да се провалят шумно | тихият no-op е най-острата граница, намерена при писането |
| Да се направи `verify` да пада при всеки деклариран маршрут, който не отговаря с 200, и да проверява, че административните страници отказват анонимни потребители | днес само `/` и входът на администратора са твърди провали |
| Да се поправят или премахнат функциите `cart` и `personalization` | `cart` не може да се включи в никоя комбинация, която минава; `personalization` не прави нищо |
| Пресетът да се избира със SHA-256 на осите, а не с `GetHashCode()` | единственото място, където една и съща спецификация може да даде различно приложение |
| Името да се раздели по език: ДПС-НН на български, Genesis на английски, `dps-nn` за изпълнимия файл | ADR-009 фиксира едно име за двете издания; двете езикови издания искат две |

Добавяне на решение: един файл в `docs/adr/`, номериран, с контекст / решение / алтернативи / последствия; връзка от мястото, което управлява; прието решение не се редактира.
