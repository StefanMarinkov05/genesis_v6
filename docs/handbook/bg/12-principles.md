# Принципи на дизайна

Пет принципа обясняват повечето решения в този код. Когато промяна се бори с архитектурата, обикновено един от тях е причината.

## 1. Детерминизмът е по подразбиране; недетерминизмът е файл

Две пускания на един lock файл дават едно приложение, освен LLM съдържанието и миграциите. Затова разнообразието е **хеш**, никога `Random` или `GetHashCode()` (в .NET той се рандомизира за всеки процес) — с едно известно изключение, описано по-долу; всеки шаблон чете вече изчисления профил; резултатът на модела е файл, който конвейерът валидира.

## 2. Детерминизмът не бива да изглежда като клонинг

Един seed определя стила на проекта, по една стойност на ос:

| Ос | Стойности |
|---|---|
| `collectionInit` | `new()` · `new List<T>()` · `[]` |
| `adminRoleName` | Administrator · Admin · Owner |
| `userRoleName` | българската дума за „Потребител“ · User · Client |
| `seedPasswordPattern` | три шаблона, всички съвместими с политиката на Identity |
| `namespaceStyle` | file-scoped · block-scoped |
| `diRegistrationStyle` | верижно · отделни изрази |
| `stringInterpolationVsConcat` | интерполация · конкатенация |
| `viewCommentDensity` | рядко · умерено |
| `bootstrapTheme` | осем Bootswatch теми |
| `navbarStyle` | три конвенции |
| `buttonShape` | pill · rounded |

Единадесет оси, по една стойност, избрана като `SHA256(seed + ":" + axis)`. Спецификацията може да закачи всяка ос; незакачените се различават между проекти и никога в един проект. Визуалната идентичност отвъд Bootstrap идва от наслагване на дизайн-пресет (ADR-008), така че „изгледът“ е избор на токени, а не стилизиране по шаблон. Пресетът е известното изключение от принцип 1: когато `meta.style.preset` не е закачен, той се избира с `GetHashCode()`, който .NET рандомизира за всеки процес, така че две пускания на една и съща спецификация могат да получат различни пресети. Закачете пресета (FaceNote го прави), докато това не бъде поправено; капанът е описан в [глава 21](21-techniques.md).

Сценарият е конкретен: един разработчик често доставя няколко проекта в едно училище, понякога в един клас, и работите се сравняват. Без разнообразие всеки студент би получил едно и също приложение, което е безполезно като оценяван артефакт и несправедливо към студентите, предали го.

Границата: стил, имена, оформление, съдържание и състав на функциите се менят; структурата на страниците остава същата, защото един набор шаблони я произвежда.

## 3. Всеки етап е отметка и всеки етап е идемпотентен

Едно генериране струва минути компилация, миграции и LLM извиквания и ще бъде прекъснато. Затова runner-ът помни завършеното по етап, а етапът сам разпознава свършената работа (наличен `.csproj`, валиден seed, приложена миграция).

## 4. Проваляй се шумно, рано и с поправката

Котва, която не намира формата си, хвърля, вместо да остави скелето непроменено (ADR-006). `spec-expand` валидира входа преди генериране; `verify` проверява манифеста преди стартиране. `doctor` отпечатва командата за поправка, а агентът спира при проблем на средата.

## 5. Една реализация, много входни точки

CLI е конвейерът. GUI го пуска и възстановява напредъка от `dps-nn.log.jsonl`; не вика класове на етапи и не преписва възобновяването. Агентният режим ползва същата машина без интерактивните избори.

## Правилото за слоевете

Зависимостите сочат навътре:

```text
Genesis.Cli  ->  Agent, Stages, Diagnostics, Pipeline   (the composition root)
Agent        ->  Llm, Spec          (reaches the pipeline only through a delegate)
Stages       ->  Pipeline, Llm, Util, Variation, Spec
Diagnostics  ->  Pipeline
Pipeline     ->  Variation, Spec
Util         ->  Variation, Spec
Variation    ->  Spec
Spec, Llm    ->  (nothing inside the core)
```

- `Spec`, `Variation` и `Util` не зависят от нищо в конвейера.
- `Llm` познава файловия договор, а не етапите.
- `Stages` може да ползва всички изброени; нищо освен CLI не ползва `Stages`. Агентът пуска конвейера през делегат, който CLI му подава, и точно това прави цикъла му тестваем без `dotnet`.
- `Diagnostics` е лист: проверява света, не генерира.

## Точки за разширяване

| Искате да… | Добавяте | Цена |
|---|---|---|
| промените съдържанието на файл | редакция на шаблон | ниска |
| добавите нов файл | шаблон + едно извикване | ниска |
| добавите повтаряща се възможност | `feature-templates/<name>.json` + условно излъчване | средна |
| добавите етап | `IStage` + окабеляване в CLI | средна |
| добавите възможност на спецификацията | схема + POCO + семантика + етап + документ | висока |
