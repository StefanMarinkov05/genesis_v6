# Справочник на CLI

Съкратено от пълния справочник в английското издание; командите и кодовете са същите.

| Команда | Какво прави |
|---|---|
| `run --all` | целият конвейер за една спецификация; пропуска завършените етапи |
| `run --all --from <етап>` | пуска отново този етап и следващите |
| `create` | агентен режим: описание → чернова → пускане → поправка на спецификацията |
| `doctor` | проверява предпоставките и отпечатва поправката за всяка липсваща |
| `spec build --notes <файл>` | чернова на спецификация от бележки |
| `spec expand` | разгръщане + `$variation:` → `project-spec.lock.json` |
| `scaffold`, `emit-models`, `identity`, `emit-controllers-views`, `seed`, `verify`, `report` | пуска един етап (за диагностика) |

## Опции

| Опция | По подразбиране | Значение |
|---|---|---|
| `--spec <път>` | `project-spec.json` | спецификацията |
| `--out <папка>` | `out` (`create`: `out/agent_<време>`) | корен на резултата |
| `--no-interactive` | изкл. | без въпроси; при нужда от въпрос — грешка |
| `--resume` | изкл. | продължава след ръчно попълнен отговор |
| `--image-provider`, `--image-pack` | `pexels` / – | откъде идват снимките |
| `--version` | – | версия и комит от `VERSION` |

## Кодове за изход

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | етап се е провалил; агентът е спрял; `doctor` намери липса |
| `2` | грешно извикване (без описание, без ключ, лоша опция) |
| `3` | LLM обмен чака ръчен отговор |

## Променливи на средата

| Променлива | Действие |
|---|---|
| `ANTHROPIC_API_KEY` | автоматични LLM обмени (иначе — файлов договор и код 3) |
| `DPS_NN_MODEL_SPEC` / `DPS_NN_MODEL_SEED` | смяна на моделите |
| `ANTHROPIC_BASE_URL` | друг адрес на API (прокси, тестов stub) |
| `PEXELS_API_KEY` / `PIXABAY_API_KEY` | истински снимки (иначе Picsum) |
| `DPS_NN_LOG_LANGUAGE=en` | английски имена на нишките в лога |
| `ConnectionStrings__DefaultConnection` | базата на генерираното приложение |

## Избор между няколко спецификации или seed-а

Без `--spec`, при няколко `project-spec*.json` (текуща папка, `fixtures/`, архивът) се показва номерирано меню; точно един кандидат се използва автоматично; явен `--spec` никога не пита. Кандидатите за seed са в `seeds/` или `prompts/out/seeds/`; изборът се копира в `prompts/in/seed-response.json`. Менютата се пропускат при `--no-interactive`.
