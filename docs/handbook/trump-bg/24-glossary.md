# Речник — най-добрите думи, имаме всички най-добри думи

Термините се определят веднъж тук; останалата книга ги ползва само с тези значения. Едно значение на
дума. Някои документи ползват една дума за три неща и три думи за едно нещо. Пълно объркване.
Като да питаш за посоката в село — всеки ти казва различно. Не тук. Всяка дума има работа и всяка дума
си върши работата.

| Термин | Значение |
|---|---|
| **Автоматичен режим** | LLM обмен, който инструментът прави сам, когато е зададен `ANTHROPIC_API_KEY`. |
| **Агентен режим** | Командата `create`: LLM пише чернова на спецификация, конвейерът върви, провалите се връщат като поправки на спецификацията. Срещу *ръчен режим*. |
| **Административен надзор** | Стъпката на разгръщането, която добавя административен CRUD контролер за всеки модел, на който спецификацията не е дала такъв, така че административната област е цяла по конструкция. |
| **Възобновяване** | Продължаване на генерирането от първия етап, който не е записан като готов. |
| **Генериран резултат** | Всичко под `out/`. За еднократна употреба и никога не се редактира на ръка. |
| **Дизайн-пресет** | Именуван набор токени (акцент, неутрални цветове, шрифтове, дълбочина) върху Bootstrap тема, заклован в `meta.style.preset` или избран за проекта със същия SHA-256 като осите на разнообразието (глава 12). |
| **Езикова проверка** | Сканирането на видимия текст за английски във `verify`; изцяло пропуснато за проекти, които не са на български. |
| **Етап** | Една стъпка от конвейера: `IStage` с име и идемпотентен `RunAsync`. |
| **Идемпотентен (етап)** | Безопасен за повторно пускане: открива собствената си завършена работа, вместо да я дублира. |
| **Инсталационен корен** | Папката само за четене, която държи инсталираната програма. Срещу *работна папка*. |
| **Кодов указател** | Именувана котва (`searchEngine`, `sorting`, `imageCrudLogic`, …), която етапът `report` решава до файл, диапазон от редове и откъс в `project-summary.json`. |
| **Компилационна порта** | `dotnet build`, който етапът трябва да мине, преди да се брои за готов. |
| **Начални данни (seed)** | Вторият вход: по един масив редове за модел, със символни препратки и фрази за снимки. Също и етапът, който го консумира. |
| **Неподдържано искане** | Запис в `meta.unsupportedRequests`, който пази нещо, поискано от описанието, но което генераторът не може да изрази. |
| **Ос на разнообразието** | Едно от единайсет копчета за стил (имена, стил на DI, имена на ролите, тема, …), решено веднъж за проекта от неговата seed стойност. |
| **Отклонение** | Декларативна промяна на контролер от scaffold: `removedActions`, `redirects`, `sorting`, `pagination`, `ownership`. Никога код в спецификацията. |
| **Отметка** | Име на етап, записано в `plan/state.json` на проекта, след като този етап успее. |
| **Порта** | Всяка проверка, която спира генерирането да продължи: схема, компилация, миграция, verify. |
| **Проверка на манифеста** | Сравнението на `verify` между файловете, обещани от спецификацията, и файловете на диска. |
| **Произход** | `generatedBy` на един контролер: `scaffold`, `template` или `writtenFromScratch`. |
| **Работна папка** | Папката с право на запис, в която работи едно генериране: `Documents\DPS-NN` при инсталация, коренът на хранилището при разработка. |
| **Ръчен режим** | LLM пътят без API ключ: инструментът пише заявка и излиза (код 3), докато не сложите файл с отговор. |
| **Собственост** | Правило за контролер (`{ "userProperty": "UserId" }`), което налага „собственик или администратор“ при промени, на сървъра. |
| **Спецификация** | `project-spec.json`, декларативното описание на приложението. |
| **Файлов договор** | Правилото от ADR-005, че всеки LLM обмен е файл заявка плюс файл отговор, еднакви в ръчния и автоматичния режим. |
| **Фрагмент на функция** | JSON файл под `feature-templates/`, който инжектира модели (понякога и контролери), когато функцията е включена; самите страници, зависещи от функцията, идват от шаблони. |
| **`$primaryModel`** | Символ във фрагмент на функция, заменян с основния модел на проекта, когато фрагментът се слива. |
| **`$seedUser:N`** | Заместител в редовете с начални данни, който значи „N-тият зареден потребител“, решен до истински Identity GUID при вмъкване. |
| **`$variation:axis`** | Заместител навсякъде в низ, който разгръщането заменя с решената за проекта стойност на оста. |
| **displayName** | Българският надпис на свойство на модел. Задължителен за всяко видимо съхранено свойство; точката на налагане на правилото „само български“. |
| **DTO** | Съставен модел за четене над няколко същности. Окабелен от край до край, но нито едно доставено приспособление още не го ползва, така че го третирайте като недоказан. |
| **`isLookup` / `isSpecification`** | Флагове на модела, които местят малките модели на административната страница „Спецификации“, като филтриран раздел само за четене или като CRUD раздел, вместо като отделни точки в навигацията. |
| **Lock файл** | `project-spec.lock.json`, разгънатата спецификация, която всъщност чете всеки етап от `scaffold` нататък. |
| **`parentRef_<Target>`** | В ред от началните данни — `refKey` на родителя, към който принадлежи този ред. |
| **`refKey`** | Уникалното символно име на ред от началните данни, което децата ползват вместо ключ от базата. |
| **Seed потребител** | Потребител, създаден от `IdentitySeeder` от `identity.seedUsers`. Освен ако спецификацията не задава такава, паролата му е изведена от seed стойността за разнообразие и имейла; всички се записват в `logs/<Project>/seed-credentials.txt`, а банерът показва един администратор и един обикновен потребител. |
| **Verify** | Етап 8 и определението на продукта за „готово“: компилация, миграция, манифест, стартиране, `/`, вход като администратор, декларираните маршрути (всеки не-200 проваля), отказ на защитените страници за анонимни, език. |

Трийсет и седем термина. Научете ги веднъж и цялата книга се отваря. Като „Сезам, отвори се“. И два
прякора, които *не* са в таблицата, защото не са официални — просто са верни: **Сънливия No-Op**,
`--from spec-build` / `--from spec-expand`, които не пускат абсолютно нищо (още е отворено, глава 25),
и **Нискоенергийния `GetHashCode()`**, старият избирач на пресета, пенсиониран в changelog 141
(глава 21).
